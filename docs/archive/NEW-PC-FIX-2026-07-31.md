## What went wrong (short version)

Three independent failures, all from the same root cause — **config that is
keyed to an absolute path does not survive a machine move**:

1. Claude memory folders are named after the project's absolute path. The new
   PC never had the site-repo memory under its own key, so every session there
   started without it.
2. The backup script *mirrored* memory rather than adding to it, so the new
   PC's 2026-07-30 run concluded the folder was gone and **deleted all 16
   files** from the repo tip (commit `8e43610`, 16 × `D`).
3. The workspace-root repo has no git remote, so the files Claude loads every
   session only ever moved by hand.

Plus two live Netlify tokens sitting in plaintext config that syncs to GitHub.

## 2. RESTORE CLAUDE MEMORY

Memory lives in `~\.claude\projects\<mangled-absolute-path>\memory\`. The folder

| Machine | Key for the site repo |
|---|---|
| Old PC | `C--Users-andyg-Desktop-cursor-mrmallorcagolf-real` |

**Step A** — open a Claude session once in each project folder so the correct
keys exist, then list what's actually there:

```powershell
Get-ChildItem "$env:USERPROFILE\.claude\projects" -Directory | Select-Object -ExpandProperty Name
```

**Step B** — copy each backed-up folder into its matching key. **Correct the
right-hand side of `$map` to whatever Step A actually printed** — do not assume
these names:

```powershell
$bk = "C:\OneDrive\Desktop\cursor\claude-config-backup\memory"
$pr = "$env:USERPROFILE\.claude\projects"

$map = @{
    "C--Users-andyg-Desktop-cursor-mrmallorcagolf-real" = "C--OneDrive-Desktop-cursor-mrmallorcagolf-real"
    "c--Users-andyg-Desktop-cursor"                     = "c--OneDrive-Desktop-cursor"
    "C--Users-andyg-Downloads"                          = "C--Users-Andy-Downloads"
}

foreach ($old in $map.Keys) {
    $srcDir = Join-Path $bk $old
    $dstDir = Join-Path $pr "$($map[$old])\memory"
    if (Test-Path $srcDir) {
        New-Item -ItemType Directory -Force -Path $dstDir | Out-Null
        Copy-Item "$srcDir\*" $dstDir -Recurse -Force
        "restored {0} -> {1}" -f $old, $map[$old]
    } else {
        "MISSING in backup: $old"
    }
}
```

**Step C** — verify counts:

```powershell
Get-ChildItem "$env:USERPROFILE\.claude\projects" -Directory | ForEach-Object {
    $m = Join-Path $_.FullName "memory"

}
```

## Standing rules that came out of this

1. **No credential ever goes in `~\.claude\settings.json`, `~\.codex\rules\`, or
   any file under `~\.claude`.** Those sync to GitHub. Env var or gitignored
   `.env` only.
2. **Memory folder names are absolute paths.** Any machine move needs a rename
   step, never a plain copy.
3. **Only one machine runs the scheduled tasks.** The old PC's are disabled —
   keep it that way unless deliberately switching primary.
4. **`git pull` before starting, `git push` before leaving.** The backup repo is
   written by two machines and diverges like any other repo. The 2026-07-30
   memory loss happened because a mirroring script resolved that divergence by
   deleting.
5. **`MMG_WORKSPACE_ROOT` and `MMG_DRIVE_ROOT` are authoritative** over any path
   written in a doc or hardcoded as a script fallback.
6. **A doc and reality disagreeing is a bug.** Fix the doc and push, don't work
   around it.
