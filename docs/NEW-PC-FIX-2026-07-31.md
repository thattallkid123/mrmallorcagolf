## 2. RESTORE CLAUDE MEMORY (the big context loss)

**What happened.** Claude memory lives in
`~\.claude\projects\<mangled-absolute-path>\memory\`. The folder name comes from
the project's absolute path, so the same repo has a different key per machine:

| Machine | Key for this repo |
|---|---|
| Old PC | `C--Users-andyg-Desktop-cursor-mrmallorcagolf-real` |
| New PC | `C--OneDrive-Desktop-cursor-mrmallorcagolf-real` |

The new PC never had the site-repo memory under its own key. Worse, the backup
script *mirrored* memory, so the new PC's 2026-07-30 backup run concluded the
folder no longer existed and **deleted all 16 files** from the repo tip
(confirmed: commit `8e43610`, 16 × `D`). They survived only in git history and
on the old PC.

Both halves are now fixed — the files are restored at `76f6d7e`, and the script
is additive so this cannot recur. What remains is putting them under the new
PC's key.

**Step A** — open a Claude session once in each project folder so the correct
keys exist, then list them:

```powershell
Get-ChildItem "$env:USERPROFILE\.claude\projects" -Directory | Select-Object -ExpandProperty Name
```

**Step B** — copy each backed-up folder into the matching key. Adjust the
right-hand names to whatever Step A actually printed:

```powershell
$bk = "C:\OneDrive\Desktop\cursor\claude-config-backup\memory"
$pr = "$env:USERPROFILE\.claude\projects"

$map = @{
    "C--Users-andyg-Desktop-cursor-mrmallorcagolf-real" = "C--OneDrive-Desktop-cursor-mrmallorcagolf-real"
    "c--Users-andyg-Desktop-cursor"                     = "c--OneDrive-Desktop-cursor"
    "C--Users-andyg-Downloads"                          = "C--Users-Andy-Downloads"
}

foreach ($old in $map.Keys) {
    $srcDir = Join-Path $bk $old
    $dstDir = Join-Path $pr "$($map[$old])\memory"
    if (Test-Path $srcDir) {
        New-Item -ItemType Directory -Force -Path $dstDir | Out-Null
        Copy-Item "$srcDir\*" $dstDir -Recurse -Force
        "restored {0} -> {1}" -f $old, $map[$old]
    }
}
```

**Step C** — verify. The site repo must show **16** files including `MEMORY.md`:

```powershell
Get-ChildItem "$env:USERPROFILE\.claude\projects" -Directory | ForEach-Object {
    $m = Join-Path $_.FullName "memory"
    if (Test-Path $m) { "{0} -> {1} files" -f $_.Name, (Get-ChildItem $m -File).Count }
}
```

Expected: site repo 16, workspace root 4, Downloads 27.

**Step D** — real proof: start a fresh Claude session in the repo and ask

## 7. CHECK YOUR CLAUDE DEFAULTS

`settings.json` currently carries:

```json
"effortLevel": "low",
"agent": "woz:code-free"
```

`effortLevel: low` makes Claude think less on every task, and `woz:code-free` is
the WOZCODE **free-plan fallback** agent, which gives up the WOZCODE MCP tools.
If those were set during a trial rather than deliberately, they're quietly
degrading every session on both machines. Decide and set them intentionally —
this is a judgement call, so nothing was changed for you.

Also in `settings.json`: `additionalDirectories` and a long tail of permission
entries point at old-PC paths (`c:\Users\andyg\Downloads\...`). Harmless, just
dead weight — worth pruning when you next touch the file.

## Standing rules that came out of this

1. **Never put a credential in `~\.claude\settings.json`, `~\.codex\rules\`, or
   any file under `~\.claude`.** Those sync to GitHub. Use an env var or a
   gitignored `.env`.
2. **Memory folder names are absolute paths.** Any machine move needs a
   rename step, not a plain copy.
3. **Only one machine runs the scheduled tasks.** The old PC's are disabled;
   keep it that way unless deliberately switching primary.
4. **`git pull` before starting, `git push` before leaving.** The backup repo is
   now written by two machines, so it diverges like any other repo — the
   2026-07-30 memory deletion happened because a mirroring script resolved that
   divergence by deleting.
5. **Check the diff when a backup run shows deletions.** Skills are still
   mirrored, so a machine missing a skill will remove it from the backup.
