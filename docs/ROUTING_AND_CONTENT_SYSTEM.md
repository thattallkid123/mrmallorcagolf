# Routing and Content System

This file describes the current route/content architecture for the multilingual site.

## Goals

- Keep URL structure stable for SEO.
- Keep locale behavior explicit.
- Reduce repeated wrapper code.
- Ensure route + sitemap parity through checks.

## Route Model

- English routes live directly under `src/app/*`.
- Non-English routes live under locale folders:
  - `src/app/de/*`, `src/app/es/*`, `src/app/fr/*`, `src/app/nl/*`, `src/app/sv/*`, `src/app/zh/*`
- Shared locale wrapper logic is centralized in:
  - `src/app/_locale/page-factories.jsx`

## Guides Model

- English guide post pages remain explicit files under:
  - `src/app/guides/<slug>/page.jsx`
- Non-English guide post pages are generated by one dynamic file per locale:
  - `src/app/<locale>/guides/[slug]/page.jsx`
- Shared `[slug]` logic is centralized in:
  - `src/app/_locale/guide-slug-factory.jsx`

## Source-of-Truth for Locales/Slugs

- Locale and slug definitions live in:
  - `src/lib/site.js`
- Main guide content lives in:
  - `src/lib/guide-post-content.js`
- Localized guide content overrides live in:
  - `src/lib/guide-post-content-localized/<slug>.js` (one file per guide; `guide-post-content-localized.js` assembles + exports the lookup)

## Safety Checks

- `npm run check:content` includes:
  - text/offer/locale checks
  - route parity checks
- Route checks:
  - `scripts/check-route-parity.mjs`
  - `scripts/check-locale-route-files.mjs`

## Indexing Guarantees

- URL paths are unchanged by wrapper refactors.
- Sitemap paths are generated from the same route model in `src/lib/site.js`.
- Route/sitemap parity checks fail CI-style checks if drift appears.

## Adding a New Guide Slug

1. Add slug to `REVIEW_POST_SLUGS` or `ARTICLE_SLUGS` in `src/lib/site.js`.
2. Add English content in `src/lib/guide-post-content.js`.
3. Add localized overrides in `src/lib/guide-post-content-localized/<slug>.js` (if available) — `guide-post-content-localized.js` itself is just the assembler/lookup, split per-guide since 2026-08-22.
4. Run:
   - `npm run check:content`
   - `npm run build`

## Notes

- Text corruption is caught at commit time by `npm run check:text` (`scripts/check-text-corruption.js`) and `npm run check:js-parse`, not patched at render time. A prior runtime mojibake-repair module (formerly src/lib/text-normalization.js) was removed 2026-08-14 after auditing found it a no-op — 0 of 2,226 strings across the content modules it wrapped would ever change, because the corruption forms actually occurring in this repo (irreversible `?` substitution, ASCII-folded accents) are not the reversible Latin-1/UTF-8 mojibake shape it detected.
